### Requirements Interview (from requirements phase)
- **Target users**: Mixed audience — both newcomers wanting quick plug-and-generate AND power users wanting full modular control. Basic/Advanced node split serves both.
- **Priority tradeoff**: Usable MVP first — get something wirable and functional fast. Known rough edges acceptable if core generation works. Iterate quickly.
- **Backend priority order**: LM Studio first, text-gen-webui second, Ollama last. All three in v0.1.0 but implementation order matters for development focus.
- **Success criteria**: Works in my workflow — can replace current LLM nodes in Flux prompt optimization workflow with cleaner wiring and equivalent or better results.
- **Options UX**: Show common subset (temperature, max_tokens, top_p, seed) by default. Less common params hidden behind advanced toggle or separate mechanism.
- **Streaming**: Complete then return. No streaming in v0.1.0. Don't design around it but don't prevent it either.
- **Versioning**: This is v0.1.0 (first functional release of larger planned scope), not a "v1". SemVer from the start.

### Design Interview (from design phase)
- **Module structure**: Subpackages by concern — nodes/, adapters/, config/, js/. Best for organizational clarity at this project size.
- **Testing strategy**: Unit tests for internal logic (adapters, config, option builders, graph introspection). Mock HTTP layer. ComfyUI node registration/execution is hard to unit test but internal logic is testable.
- **Adapter dispatch**: Provider dict carries adapter type key. Generation node looks up adapter class from a registry dict. Simple, explicit.
- **Menu category**: "LLM Bikeshed" with subcategories (LLM Bikeshed/providers, LLM Bikeshed/generation, LLM Bikeshed/options, LLM Bikeshed/utils).

## Learnings

- P-10 RESOLVED: PROMPT hidden input enables graph introspection for unload deferral.
- BOOLEAN widget type is first-class primitive with reliable save/load.
- Ollama options field uses `additionalProperties: true` — unknown params safely ignored.
- LM Studio default TTL is 60 minutes (our default is 30s for VRAM reclamation).
- text-gen-webui supports separate admin-key from api-key.
- `requests` (sync HTTP) is standard for ComfyUI node FUNCTION methods.
- Custom types are just uppercase strings — no registration needed.
- Design review added: text-gen-webui model loading lifecycle (FR-19), Load Text File node (FR-20), model selection priority (FR-21), Ollama Core/Extra Options split.
- Hidden input `prompt` (PROMPT) and required input `prompt` (STRING) share name — no collision because hidden inputs come through `**kwargs` while required inputs are named parameters. Standard ComfyUI pattern.
- Adapter instances should be singletons (stateless) — registry dict with pre-instantiated objects, looked up by `provider["adapter"]` key.
- PromptServer endpoints should be per-backend (not single endpoint with type param) for cleaner routing and independent testability.
- Options chaining via `options_in` at the options node level keeps generation nodes simple — they receive a single merged dict.
- `folder_paths.get_input_directory()` is the portable way to find ComfyUI's input folder for the Load Text File node.
- text-gen-webui unload failure should be non-fatal (warning log) since the generation itself succeeded — VRAM may not be freed but user's result is intact.
